# UX review and changes, 12 November 2026

What was looked at, what was found, what was changed, and what is still open.
This file describes its date. The plan it leaves behind is in
[ROADMAP.md](../ROADMAP.md); the completed changes are in
[CHANGELOG.md](../CHANGELOG.md).

## Why

The owner's direction for this pass: the site should work for people, not
only look good; Bitbaum should become a platform for builders, not only a
studio; shared packages are used, and changed where they fall short.

## How it was looked at

- Every page was opened in a real browser at 390px and 1440px, light and dark,
  and read one screen at a time.
- The eight journeys the site exists for were walked with the network mocked,
  so nothing was sent to the studio: commissioning, applying as a builder,
  hiring a builder, building with Loki, the course, coming back with and
  without a link, finding a package, replying from a project page.
- The generator, the stylesheet and all fifteen gates were read, so a change
  would move the gates with it rather than around them.
- Loki's studio routes, accountkit, sitekit and the shared sign-in service were
  read for what a static site can honestly offer as "sign in".

## What was changed in other repositories

- **chatkit** ([#84](https://github.com/bitbaum/chatkit/pull/84)): the cause of
  the scroll. A thread holding only a greeting, on a page, no longer takes the
  page to its own end; the reader's first message starts the following. A
  browser test covers it and fails on the released version.
- **Loki** ([#1672](https://github.com/bitbaum/loki/pull/1672)): the backend
  half of signing in from this site. `GET /api/studio-session` tells this
  origin who is looking (a name, a handle, a picture, whether they run the
  studio, their builder applications by status; never an email, an id or a
  key), and `/studio/return?to=/builders/` signs a person in and brings them
  back to the page they were on.
- **accountkit** and **sitekit**: changes are in progress on the branch
  `ccr-b610fdf3-kt9gj1` of each repository and are listed in ROADMAP.md under
  "Sign in from the studio site" and "Move the chrome to sitekit".

## What is still open

In the order it should be done. Each has its line in ROADMAP.md.

1. **Sign in from the header.** It needs Loki #1672 deployed and accountkit's
   account control released. Until then the only sign-in is "Builder sign-in",
   which leads to Loki's page for an approved builder who connected an account.
2. **A builder workspace opened by an account.** Today a signed-in builder can
   only have a new private link made, which ends the old one. Loki needs
   routes that authorise by account instead of by link.
3. **The first profile in the directory.** It is empty. The page says so.
4. **Header, menu and footer from sitekit.** Measured against this site, sitekit
   needs nine changes first; three are defects that affect its current
   adopters. `package-plan.json` records why the chrome is still local.
5. **Two kinds of receipt for one request.** A first message with no website
   address becomes a note with a Loki tracking link, not a portal; if an
   address comes later the portal link replaces it. A founder describing a new
   product therefore gets no portal and no "Lost the link?". This needs a
   request kind on Loki for an idea without a website (already on the roadmap).
6. **The private link lives only in the tab.** It is kept in session storage and
   taken out of the address bar, so a new tab or a bookmark loses the request.
   Keeping it longer is a decision about shared computers, and it is the
   owner's.
7. **The approved builder's portal is one long page.** Eight sections, 5.2
   screens on a phone, three primary buttons on one preview screen.
8. **Package pages.** The install command sits below the first screen and can
   lag the registry, because the version comes from Fleet's package register.
9. **Search.** `/work/` and `/packages/` filter by substring. Pull request
   [#297](https://github.com/bitbaum/bitbaum/pull/297) moves both to searchkit
   and is waiting on the package rollout gate.
10. **Weight.** The home page loads 1.3 MB before it is ready, 726 KB of it
    nine screenshots at 1280×800 shown about 330px wide. A smaller size per
    screenshot would more than halve it.
11. **The stylesheet.** 56 distinct font sizes, 13 breakpoints and about 8 KB
    that no page uses. This pass unified the buttons and fixed alignment; the
    type scale is untouched.

## Decisions that are the owner's

- **How far up the builder moves.** The builder now has a door on the first
  screen, but `site/PURPOSE.md` still orders the readers with the person who
  commissions work first, and the headline is still "One trunk. Many
  products."
- **The name on the sign-in button** once the header has one: "Sign in", or
  "Sign in with OrangeCat". The portal, the private page and Loki's own
  sign-in page use three different names today.
- **Whether a request may be kept on a device** beyond the tab it was made in.
